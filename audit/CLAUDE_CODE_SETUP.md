# Инструкция: как вести редизайн AiRemOne через Claude Code

Этот документ — операционный слой поверх `PROMPT_FOR_DESIGN.md`. Там — **что** делать (контент, структура, бизнес-факты). Здесь — **как** это делать инструментами Claude Code: какой скилл вызывать, как зафиксировать design system файлами (а не только текстом в чате, который забывается между страницами), и в каком порядке собирать сайт, чтобы все 10+ страниц не разъехались по стилю.

Важное уточнение: то, что вы называли «Cloud Design» — это и есть Claude (Claude Code/Claude.ai). Отдельного стороннего инструмента с таким названием не существует — я исхожу из того, что дальнейшую разработку вы продолжите здесь же, в Claude Code, либо в новом чате Claude.ai.

---

## 0. Почему не просто вставить промпт в чат и не Artifacts

Artifacts (панель предпросмотра в Claude.ai) отлично подходят для того, что уже сделано — макеты одного экрана. Но это не подходящий инструмент для **боевого** 10–12-страничного сайта с формами, интеграцией с Telegram и деплоем: там жёсткий лимит на размер, нет полноценной файловой структуры проекта, нет git/деплоя.

Для реальной разработки нужен **Claude Code** (этот инструмент) с настоящим репозиторием: файлы, git, установка зависимостей, деплой. Промпт из `PROMPT_FOR_DESIGN.md` вставляется не в чат-подсказку, а как первое сообщение новой сессии Claude Code в новом (боевом) репозитории проекта.

## 1. Какие скиллы понадобятся и когда

В этой среде уже доступен набор Anthropic-скиллов для дизайна/фронтенда. Используйте их по ходу работы, а не только на старте:

| Скилл | Когда вызывать | Зачем |
|---|---|---|
| **`anthropic-skills:impeccable`** | Всегда, с самого начала | Главный скилл для дизайна/редизайна интерфейсов. Держит «потолок качества»: продакшен-грейд код, без дженерик-AI-вида, с проверкой на моб./десктоп. Имеет подкоманды: `init` (зафиксировать контекст проекта), `shape`/новая работа (спроектировать страницу до кода), `polish` (финальная доводка), `critique`/`audit` (проверка UX и техники — a11y, perf, адаптив), `bolder`/`quieter` (усилить/приглушить), `animate` (анимации конкретного узла), `harden` (продакшен-готовность: ошибки, edge cases), `adapt` (адаптив под устройства). |
| **`anthropic-skills:svg-animations`** | При создании иконок/лайн-арт иллюстраций (как в макетах — плашки «Фото объекта») и логотипа | В макетах уже используются однолинейные SVG вместо фото — этот скилл нужен, чтобы довести их до полноценной авторской иконографики и, при желании, анимированного логотипа. |
| **`anthropic-skills:animate`** | Точечно — для конкретных сложных интеракций (слайдер «до/после» в портфолио, шаги калькулятора, таймлайн «как мы работаем») | Даёт осознанный процесс: нужна ли анимация вообще → какое свойство анимировать → кривая/длительность → поведение при прерывании. Предотвращает «анимацию ради анимации», о которой вы просили не перебарщивать. |
| **`anthropic-skills:apple-design`** | Если хочется, чтобы драг-слайдер «до/после» и шаги калькулятора ощущались физично (инерция, прерываемость) | Опционально, но для тактильных интеракций (перетаскивание) даёт правильный физический язык жестов. |
| **`anthropic-skills:review-animations`** / **`improve-animations`** | На этапе финальной проверки, когда основные страницы уже собраны | Ревью уже написанной анимации против высокой планки качества — отдельный незамыленный взгляд перед сдачей. |
| **`anthropic-skills:imagegen`** | Только если решите не использовать реальные фото объектов, а нужны иллюстративные изображения (например, для блога) | Для реальных объектов ремонта лучше настоящие фото компании — они сильнее для доверия в этой нише, чем любые сгенерированные. |
| **`anthropic-skills:security-best-practices`** | Как только пишете код форм/бэкенда (приём заявок, интеграция с Telegram Bot API) | Формы собирают телефон/email — нужна защита от спама (honeypot), валидация на бэкенде, никаких секретов/токенов в клиентском коде. |
| **`security-review`** | Перед деплоем в прод, на финальном branch/diff | Общая проверка безопасности перед тем, как сайт станет публичным. |
| **`code-review`** | Перед каждым мержем крупного куска (например, после сборки каждой страницы) | Держит качество кода на всём проекте, а не только дизайн. |

Не нужны в этом проекте: `dataviz` (нет графиков/дашбордов), `xlsx/pptx/docx/pdf` (не про сайт).

## 2. Порядок работы (пошагово)

1. **Новый репозиторий** для боевого сайта (не в этом же репо с аудитом — тут только материалы для выбора направления). Например `airemone-site`.
2. **Первое сообщение новой сессии Claude Code** — используйте промпт из раздела 4 ниже. Он просит Claude:
   - сначала вызвать `/impeccable` → `init`, чтобы зафиксировать бизнес-контекст в `PRODUCT.md` (один раз, на весь проект — дальше не пересоздаётся);
   - затем зафиксировать выбранное визуальное направление в `DESIGN.md` (см. раздел 3 — там точные токены, чтобы Claude не «сочинял» палитру заново на каждой странице).
3. **Собирайте сайт по одной странице**, начиная с Главной — она самая насыщенная и на ней «откатается» вся дизайн-система (кнопки, карточки, формы, анимации). Дальше остальные 10 страниц идут быстрее, потому что переиспользуют те же компоненты/токены.
4. **После каждой крупной страницы** — `code-review` на диф, и раз в 2-3 страницы `/impeccable critique` (проверка на дженерик-AI-вид, за которым вы просили следить).
5. **Точечные анимации** (слайдер до/после, калькулятор, таймлайн) — вызывайте `anthropic-skills:animate` отдельно на этот конкретный узел, не на всю страницу разом.
6. **Когда все страницы собраны** — финальный проход: `/impeccable polish` → `/impeccable audit` (a11y, скорость, адаптив) → `review-animations` → `security-review` на формы/бэкенд.
7. **Деплой** — см. `AUDIT.md`, раздел 11 (рекомендация: статический сайт, Vercel/Netlify или VPS на территории РФ из-за 152-ФЗ, т.к. собираете персональные данные).

## 3. Design system — токены выбранного направления

Ниже — готовые файлы `tokens.css` для всех трёх вариантов (взяты из `NOTES.md` соответствующих макетов в `designs/`). **Оставьте только токены вашего варианта**, остальные удалите — это то, что вы вставите как `DESIGN.md`/`tokens.css` в новый проект, чтобы Claude Code не придумывал цвета заново на каждой странице, а ссылался на один источник истины.

### Вариант A — Тёплый эдиториал

```css
:root {
  --bg: #F6F1E9;
  --bg-alt: #EFE7D8;
  --surface: #FFFFFF;
  --ink: #211C16;
  --ink-soft: #5B4F41;
  --accent: #B5502E;
  --accent-soft: #E4C9B8;
  --accent-2: #7C8A6E; /* вторичный, использовать редко */
  --line: #DED2BB;

  --font-display: "Fraunces", serif;
  --font-body: "Manrope", sans-serif;
}
```
Google Fonts: `https://fonts.googleapis.com/css2?family=Fraunces:opsz,wght@9..144,400..600&family=Manrope:wght@400;500;600;700&display=swap`

Motion language: fade+rise scroll-reveal (стаггер 80–120ms), анимированные счётчики, лёгкий параллакс на фото-плашках, подчёркивание nav-ссылок рисуется при hover, тонкий grain-оверлей (SVG feTurbulence, ~3–4%).

### Вариант B — Тёмная премиум-мастерская

```css
:root {
  --bg: #14120F;
  --bg-alt: #1C1914;
  --surface: #211D17;
  --ink: #F4EEE2;
  --ink-soft: #B7AC98;
  --accent: #CFA35C;
  --accent-bright: #E8C077;
  --line: rgba(244, 238, 226, 0.12);

  --font-display: "Bricolage Grotesque", sans-serif;
  --font-body: "Plus Jakarta Sans", sans-serif;
}
```
Google Fonts: `https://fonts.googleapis.com/css2?family=Bricolage+Grotesque:wght@200..800&family=Plus+Jakarta+Sans:wght@400;500;600;700&display=swap`

Motion language: Ken Burns на фото-плашках (scale 1→1.08), scroll-reveal карточек, счётчики со свечением при завершении, SVG-чертежи «дорисовываются» (stroke-dashoffset), bronze-glow при hover, всё на мягком cubic-bezier.

### Вариант C — Динамичный конструктор

```css
:root {
  --bg: #FAF8F3;
  --ink: #16140F;
  --accent: #FF4B12;
  --accent-2: #FFD400; /* очень дозированно, максимум 2-3 применения на сайт */
  --line: #16140F;
  --shadow-offset: 6px; /* жёсткая офсетная тень без блюра */

  --font-display: "Unbounded", sans-serif;
  --font-body: "Manrope", sans-serif;
}
```
Google Fonts: `https://fonts.googleapis.com/css2?family=Unbounded:wght@400..900&family=Manrope:wght@400;500;600;700&display=swap`

Motion language: бесшовная бегущая строка услуг (pause on hover), scroll-reveal с edge-стаггером, hover-tilt на карточках (rotate 1–2deg + смещение тени), счётчики, курсор-точка в hero (только десктоп, lerp через rAF, отключена на touch).

## 4. Готовый промпт для первого сообщения в новой сессии Claude Code

Скопируйте целиком (оставив только нужный вариант в блоке «Design system» — см. раздел 3 выше, вставьте выбранный набор токенов вместо плейсхолдера) и отправьте как первое сообщение в новой Claude Code сессии, открытой в **пустом боевом репозитории** проекта.

=== НАЧАЛО ПРОМПТА ===

Мы начинаем разработку продакшен-сайта AiRemOne (ремонт квартир под ключ, Москва) с нуля, в этом репозитории. Веди себя как senior продуктовый дизайнер и frontend-разработчик топовой студии — продакшен-грейд код, без дженерик-AI-вида (никаких фиолетово-синих градиентов, карточек «иконка в кружке» без индивидуальности, Inter/Roboto без иерархии, glassmorphism на каждом углу).

**Порядок действий:**

1. Вызови скилл `anthropic-skills:impeccable` (через Skill-инструмент) и пройди его `init`, чтобы зафиксировать контекст проекта в `PRODUCT.md`. Бизнес-контекст для init:
   - AiRemOne, ремонт квартир под ключ и дизайн-интерьеров, Москва.
   - Телефон +7 (980) 499-88-80, email airemone2@gmail.com, адрес г. Москва, ул. Барклая, 6, к.2, часы Пн–Пт 9:00–20:00, Сб–Вс 10:00–18:00.
   - Позиционирование: честный ремонт без скрытых платежей — фикс. смета, официальный договор, фотоотчёт в Telegram, гарантия 3 года, СРО/ISO 9001.
   - Целевая страница = Persuade-режим (посетитель должен решить и позвонить/оставить заявку) для главной/цен/дизайна; Operate-режим для калькулятора (задача — довести до результата расчёта); Read-режим для блога, если будет.

2. Затем зафиксируй design system в `DESIGN.md` и `src/styles/tokens.css` (или эквивалент под выбранный стек) — вот точные токены выбранного направления, использовать без изменений на всех страницах:

```
[ВСТАВЬТЕ СЮДА БЛОК ТОКЕНОВ ВЫБРАННОГО ВАРИАНТА ИЗ РАЗДЕЛА 3 ВЫШЕ]
```

3. Стек — статический сайт (рекомендация: Astro) с лёгким vanilla JS для интерактивных виджетов (калькулятор, слайдер до/после, аккордеоны). React/Next.js — только если в ближайших планах личный кабинет клиента с отслеживанием статуса ремонта онлайн; если это не так, не добавляй React.

4. Структура сайта, контент блоков, бизнес-факты и требования к анимациям — полностью описаны в приложенном ниже брифе (это отдельный документ, следуй ему как основному источнику правды по контенту и структуре страниц):

[СЮДА ВСТАВЬТЕ ПОЛНОЕ СОДЕРЖИМОЕ audit/PROMPT_FOR_DESIGN.md — разделы А, В, Г, Д, Е, Ж, З, с выбранным вариантом в разделе Б]

5. Есть готовые дизайн-макеты выбранного направления (папка `designs/variant-…` из предыдущей сессии) — если можешь их открыть/тебе их приложили, используй как точный визуальный референс по деталям: скругления, тени, motion timing, breakpoints. Не копируй код макетов один в один (это одностраничные демо без реальной структуры проекта), но следуй их визуальному языку буквально.

6. Собирай сайт по одной странице, начиная с Главной. После неё — вызови `anthropic-skills:animate` точечно на слайдер «до/после» и таймлайн «как мы работаем» (не на всю страницу разом). Каждые 2–3 страницы — `code-review` на диф.

7. Когда все страницы готовы — финальный проход: `/impeccable polish`, затем `/impeccable audit` (доступность, скорость, адаптив на 375/768/1024/1440), затем `review-animations`, затем `security-review` на формы и интеграцию с Telegram Bot API (без секретов в клиентском коде, honeypot от спама, валидация на сервере).

Начни с шага 1.

## 5. Если скилл `impeccable` не отвечает / файлы не подгружаются

В части сессий вспомогательные файлы скилла (`reference/*.md`, `scripts/`) могут быть недоступны из-за синхронизации окружения — сам скилл тогда явно об этом предупредит и предложит продолжить на общих принципах хорошего дизайна без своего внутреннего движка проверок. Это не блокер: просто попросите Claude Code продолжить по промпту выше и своими силами (он всё равно знает принципы из раздела 3 — конкретные токены и motion language уже зафиксированы текстом, это не зависит от доступности скрипта).
